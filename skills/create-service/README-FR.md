# Créer des services

Pour tout agent à qui vous voulez faire fabriquer des services pour Allkin. Un service est ce qui
relie Allkin à une API externe : une définition — des données, jamais du code — qui dit où se
trouve l'API, comment la clé voyage, comment tester la connexion, quels appels attendent votre
approbation, et ce qu'un agent doit savoir pour s'en servir. Avec cette compétence, l'agent réunit
ces éléments avec vous, écrit la définition et son aide dans les quatre langues dans son
**atelier** (le dossier `workshop/` de son propre dossier), la vérifie selon le standard d'Allkin
et la corrige jusqu'à ce qu'il ne reste rien à reprendre.

C'est la clé des outils de l'atelier : un agent qui l'a les reçoit — la liste de ses projets et
leur vérification —, un agent qui ne l'a pas n'en a aucun. Ce que l'agent écrit apparaît dans la
page **Services**.

Elle n'élargit aucun droit : ni commande, ni réseau, ni accès à un service ne viennent avec
elle — pas même à celui qu'il écrit. **Vous seul connectez** un service, dans cette page, avec une
clé que l'agent ne voit jamais et qu'il ne faut jamais lui donner, et vous seul l'accordez aux
agents. La signature de requêtes et le transport de courrier restent hors de portée d'une telle
définition. Vous seul donnez cette compétence à un agent.
