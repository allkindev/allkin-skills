# From OpenClaw and NanoClaw to Allkin

What each piece of the other platform becomes in Allkin. The rule of the whole migration: **what
maps simply is carried over; everything else goes on the to-do list** — never a new mechanism,
never a right granted, never a secret copied.

## OpenClaw

An OpenClaw install is `~/.openclaw/`: `openclaw.json` (JSON5), one workspace per agent
(`workspace/`, `workspace-<id>/`), `skills/` (managed competences), `cron/jobs.json`,
`credentials/` and `agents/<id>/sessions/` (left behind by `unpack`).

| OpenClaw | Allkin | How |
|---|---|---|
| `IDENTITY.md` (name, emoji, vibe) | the agent's name and description; the start of the role | `agent.json` `name`, `description` |
| `SOUL.md` (persona, tone, limits) | the role, `CLAUDE.md` | rewritten, see "Writing the role" |
| `AGENTS.md` (operating manual) | the role, `CLAUDE.md` | keep the rules of work; drop the boot sequence (Allkin loads role and memory itself) |
| `TOOLS.md` (notes on local tools) | the role, a short "Your tools" section | only what still holds in Allkin |
| `USER.md` (who the user is) | **proposed** facts about the user | listed in the report: the user adds them from their profile, or the agent proposes them later with its memory tools; never written for them |
| `MEMORY.md` | the agent's memory, `memory.md` → `memory.json` | the durable facts, one per line, 300 characters each, 4,000 in all |
| `memory/YYYY-MM-DD.md` (daily notes) | files of the agent, `data/notes/` | copied as they are; the role says they exist |
| `HEARTBEAT.md` + `heartbeat.every` | an **Action** on a schedule waking the agent | on the to-do list (or created, see "Actions") |
| `cron/jobs.json` | **Actions** on a schedule | same |
| `skills/<id>/` (workspace or managed) | a competence in `migration/repo/skills/<id>/` | `convert_skill`; given with `skillIds` |
| `agents.defaults.model.primary` | the agent's model | `anthropic/claude-x` → `claude-x`; another provider → no model, noted |
| `channels.telegram` | the integration **Telegram** (`telegram-bridge`) | to install and connect, on the to-do list |
| `channels.discord`, `slack`, `matrix`, `mattermost` | the **service** of the same name, if Allkin has one | to connect, on the to-do list |
| `channels.whatsapp`, `signal`, `imessage` | nothing yet | on the to-do list as "no equivalent" |
| `tools.browser` / web search | the rights "Web" (and "Browser") | asked in `agent.json`, granted by the user |
| `tools.exec` / shell | the right "System access" | asked; every command is then approved on a card |
| sessions (transcripts) | — | not migrated |

## NanoClaw

A NanoClaw install is a clone of its repository: `groups/<folder>/` per chat group, `store/messages.db`
(SQLite: scheduled tasks, registered groups), `.env`, `container/`, `.claude/skills/`.

| NanoClaw | Allkin | How |
|---|---|---|
| a group `groups/<folder>/` | an agent | one archive per group the user keeps |
| v1: `groups/<folder>/CLAUDE.md` | role **and** memory, mixed | split them: instructions → `CLAUDE.md`, facts → `memory.md` |
| v2: `groups/<folder>/CLAUDE.local.md` | the agent's memory | facts → `memory.md`; the group's `CLAUDE.md` is generated by NanoClaw, read it only for the role |
| `groups/global/CLAUDE.md` (v1), `container/CLAUDE.md` (v2) | a part of every agent's role | merged into each role, shortened |
| other files of a group | files of the agent, `data/` | copied |
| `scheduled_tasks` (cron, interval, once) | **Actions** | to-do list, or created |
| `container/skills/<id>/` | competences | `convert_skill` |
| `.claude/skills/<id>/` (`add-telegram`, `setup`…) | **nothing** | they change NanoClaw's code; say so once, list them, convert none |
| the group's channel (WhatsApp `@g.us`, `tg:`, `dc:`) | integration or service | as for OpenClaw |
| `.env` (names only, kept by `unpack`) | the services' forms | which secrets the user will have to enter again, by name |
| the main group's admin powers | rights of the page | asked, never granted |

## Actions

Allkin's Actions run an agent at a time (a crontab line) or on an event of its journal.

- A cron expression stays as it is (five fields). An interval of N minutes becomes `*/N * * * *`
  (hours: `0 */H * * *`; a day: `M H * * *` at the hour the user wants). A one-time task in the
  past is dropped and said.
- The message of the action is the task's prompt; for a heartbeat, the content of `HEARTBEAT.md`.
- **You create them only if** you have the right "Can schedule actions" **and** the competence
  "Manage actions" (`schedule_task`), the agent exists in Allkin (after the import), and the user
  approves each one on its card. Otherwise they go on the to-do list, written so the user can
  create them in a minute: agent, schedule, message.

## Models

Allkin runs agents on the Claude Agent SDK with the AI account the user chose. A model of the
form `anthropic/<id>` or `claude-…` keeps its id without the prefix; any other provider's model
is left out (the agent gets the account's default) and the report says so.
